# Прогресс каждого игрока между сессиями

Статус: требование владельца (2026-10-28), **предложения из таблицы владелец подтвердил** (2026-10-28). **Основное сделано** (2026-10-28, `tests/progress.txt` и `tests/level-change.txt` проходят), что осталось — в конце.

## Как должно быть в игре

Хост поднимает сервер с сохранения хоть через неделю. Игрок, который играл раньше, заходит и получает **своё**: оружие, патроны, броню. Порядок входа и то, кто сейчас онлайн, не важны. Новый игрок получает стартовое снаряжение.

## Что уже есть в FarCryCoop

- Сохранения в файл, переживают перезапуск игры: `Mods\FarCryCoop\save_<имя>.lua` (автосейв на чекпоинтах, F6/F7, `coop_savegame`). В них карта, состояние миссии и для каждого игрока позиция, здоровье, броня, оружие, патроны.
- **Но записи игроков раздаются по порядку входа** (`CoopApplyLoad`: `save.players[i]`, а если записей меньше — первая). Зашёл другим по счёту — получил чужое снаряжение.
- Перенос оружия между картами (`CoopSaveLoadouts`/`CoopApplyLoadouts`) — по номеру слота сервера, живёт только пока запущена игра. Переподключился — номер другой, снаряжение потеряно.

## Решения

| Вопрос | Решение (подтверждено) |
|---|---|
| По чему узнавать игрока? | По Steam ID, если игрок зашёл через Steam (у FarCryCoop есть мост Spacewar, `games/far-cry/steam`), иначе по имени из лаунчера. Имя среди друзей подделать можно, но для кооператива это не страшно. |
| Что хранить для игрока? | Оружие, патроны, броню, текущее оружие. |
| Здоровье? | При входе полное (не сохранять: через неделю зайти с 10 hp обидно). |
| Позиция? | Не своя старая, а у точки возрождения команды (команда могла уйти вперёд). |
| Игрок пропустил несколько карт | Получает своё последнее снаряжение (не догоняет команду по оружию). |
| Новый игрок | Стартовое снаряжение текущей миссии, как в одиночной игре. |
| Когда записывать | На чекпоинте, при смене карты, при выходе игрока и при выключении сервера. |
| Где хранится | У хоста, в файле сохранения (одна запись на игрока). Если сервер поднимет другой человек, прогресс не переедет. |

## Как сделано (2026-10-28)

- Ключ игрока: клиент сам присылает его серверу командой `COOPID` при каждом появлении (`Scripts/COOP/ClientStuff.lua`). Это `COOP_PlayerKey`, если его задал лаунчер, иначе `p_name` игры. Если два игрока прислали одно имя, второй получает `<имя>#2`. Клиент без `COOPID` (старая версия мода) узнаётся по номеру слота до конца сессии.
- `COOP_Progress[ключ]` — снаряжение как в одиночной игре: оружие, запасы, магазины и режимы огня, выбранное оружие, тип гранаты, броня, бинокль, фонарик, очки. `COOP_Owed[ключ]` — выдать при следующем появлении этого игрока.
- Запоминается: при смене карты (все), при отключении игрока, при сохранении (чекпоинт, F6, `coop_savegame`). В файл сейва пишется `progress` — все, кто когда-либо заходил, включая тех, кого сейчас нет. Записи игроков в сейве сопоставляются по ключу; старые сейвы без ключей — по порядку входа, как раньше.
- После загрузки сейва игрок, которого нет в его записях, ставится к точке возрождения команды и получает то, что сейв хранит для его ключа, иначе стартовый набор миссии.
- `CoopLoad` перенесён в `Scripts/Multiplayer/AvailableMods.lua`: лаунчер продолжает кампанию с сейва вызовом `CoopLoad("<имя>")` из меню, а раньше функция появлялась только с правилами кооп-карты, и вызов из меню падал (`attempt to call global 'CoopLoad'`).

## Что осталось

- Лаунчер не передаёт в игру ни имя из лобби, ни Steam ID: ключ сейчас — `p_name` из `system.cfg`. Нужно, чтобы лаунчер писал `COOP_PlayerKey` (Steam ID, если игрок зашёл через Steam, иначе имя из лобби) в строку настроек.
- Запись в файл при выключении сервера и при отключении игрока: сейчас между чекпоинтами это живёт только в памяти, падение сервера теряет снаряжение с последнего сохранения.
- Позиция переподключившегося посреди карты игрока (не после загрузки сейва) не проверена: он появляется там, где его ставит FarCryCoop.

## Как проверяем (харнес)

- `tests/progress.txt`: хост + client1 со своими наборами, сохранение, `down`. Новый сервер с этого сейва (`CoopLoad` из меню), входят client1 и новый client2: хост и client1 получают своё, client2 — стартовое (на Training ничего).
- `tests/level-change.txt`: Training → Carrier с узнаваемыми наборами у хоста и клиента, сравнение на сервере и у клиента; затем клиент переподключается на Carrier и получает своё обратно.
